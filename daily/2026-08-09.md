# 2026-08-09 — 模块 3 第 3 天：LI.FI SDK 实操（lifi_routes.py）

> 共学第 5 天 | 任务：写脚本调 `/quote` + `/advanced/routes`，解析多路由，按净收益排序输出 Top3
> 产出：`experiments/lifi_routes.py`（本地可运行，真实 API 数据）

---

## 一、脚本设计

### 核心逻辑

```
1. GET /quote              → 单条最优报价（跨链同币）
2. POST /advanced/routes   → 返回多条路由
3. 逐条解析 → 净收益 = toAmount - fromAmount（LI.FI 已扣全部费用）
4. 按净收益降序 → 输出 Top3
```

### 默认场景（可 CLI 覆盖）

```
10,000 USDC：Arbitrum (42161) → Ethereum (1)
fromToken: 0xaf88d065...（Arbitrum USDC）
toToken:   0xA0b86991...（Ethereum USDC）
slippage: 0.5%
```

### 关键实现点

- **费用解析兼容两种结构**：quote 的 `gasCosts/feeCosts` 在顶层 `estimate` 里，advanced/routes 的在每个 `step.estimate` 里 → `_sum_cost()` 两个位置都取
- **`toAmount` 位置差异**：quote 在 `estimate.toAmount`，route 在顶层 `toAmount` → 兼容取
- **时长**：route 的 `executionDuration` 在每步 `estimate` 里 → 求和
- 成本直接用 `amountUSD` 字段（LI.FI 已折算美元），不用自己换算

## 二、真实运行结果（08-09 实跑）

### ① 单条最优（GET /quote）

```
❌ 净收益 -25.00 USD (-0.25%) | 到账 9975.00 USDC | 时长 20s | gas $0.02 + 费 $25.01 | eco
```

### ② 多路由 Top3（POST /advanced/routes，共返回 17 条）

```
#1 ❌ -25.00 USD (-0.25%) | 到账 9975.00 | 20s    | eco
#2 ❌ -25.00 USD (-0.25%) | 到账 9975.00 | 1080s  | polymerStandard
#3 ❌ -25.78 USD (-0.26%) | 到账 9974.22 | 18s    | lifiIntents
...17 条全部净亏损
```

### 结果解读：17 条路由全军覆没，但这是最好的教学结果

```
10,000 USDC Arb→Eth：
  LIFI Fixed Fee（固定费）  = $25.00  ← 大头！与路由无关
  桥费/协议费               = $0.01-$2.8（因路由而异）
  gas                       = $0.01-$0.03
  → 无论走哪条桥，固定费 $25 先把利润吃光
```

**关键发现（实锤周报认知）**：
1. **LI.FI 自身收 $25 固定费（LIFI Fixed Fee）**——比 08-08 笔记假设的桥费 $18 还高，且**每条路由都收**，与金额无关
2. **桥费是固定成本的实锤**：10,000 USDC 全被 $25 吃掉，净亏 0.25%
3. 收益率 -0.25% 意味着：**要覆盖固定费，要么单笔金额 > $10K+，要么找到无 LI.FI 固定费的路径**
4. `executionDuration` 差异巨大（5s ~ 1200s）：Across 5s vs polymerStandard 1080s——同样成本下时间窗口完全不同

### 对信号闸门的修正建议

```
08-08 的触发条件 ① 净收益 > $10 需要修正：
  真实跨链成本 ≈ $25 固定费 + gas
  → 单笔金额必须 ≥ $25 / (预期收益率) 才有意义
  → 例：目标收益率 0.3%，则单笔 ≥ $8,333；0.1% 则 ≥ $25,000
  → 小额场景直接放弃跨链套利（08-11 策略假设时重点考虑）
```

## 三、踩坑记录

| 坑 | 现象 | 解法 |
|---|---|---|
| `options.order` 枚举不合法 | `/advanced/routes` 返回 400 `order must be equal to one of the allowed values` | 去掉 `order` 字段，自己按净收益排序 |
| quote 的 `toAmount` 不在顶层 | 解析出 0 → 净收益 -100% | 兼容 `estimate.toAmount` |
| advanced/routes 费用在 step 级 | gas/fee 显示 $0 | `_sum_cost()` 顶层 + steps 双取 |
| 时长字段位置 | duration 显示 0 | route 级没有 → 从每步 `estimate.executionDuration` 求和 |

**教训**：LI.FI 的 quote 和 advanced/routes 返回结构不对称（费用/金额/时长位置不同），解析必须兼容两种结构；先 curl 原始响应再写解析，别猜字段。
