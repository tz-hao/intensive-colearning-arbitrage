## 一、LI.FI 在做什么

### 不是流动性提供者，是路由引擎

```
Uniswap:     你有钱，池子有钱，直接交易
LI.FI:       你不关心对手方是谁 —— 你只说"从哪到哪"
             它扫描所有 DEX + 所有桥，算最优路径
```

**LI.FI 聚合的对象**：

| 层级 | 聚合内容 | 例子 |
|------|---------|------|
| DEX 聚合 | 所有链上 DEX 流动性 | Uniswap V3, PancakeSwap, Curve, Balancer |
| DEX Aggregator | 聚合器本身 | 1inch, Paraswap, 0x, OpenOcean |
| 桥 | 跨链桥协议 | Stargate V2, Across, Relay, cBridge, Hop |
| Solvers | 意图执行网络 | 基于竞争的 solver 报价 |
| Yield | 收益协议 | 各种 Vault、Staking 协议（通过 Composer） |

**一句话**：LI.FI 不问「哪个池子最好」，它把所有池子当数据，算完告诉你最佳路径。

### 四个核心动作

```
1. Aggregate  → 扫描所有桥、DEX、Solver、收益协议
2. Normalize  → 抹平 USDC vs USDC.e、不同链 token 地址差异
3. Calculate  → 在价格/速度/Gas/可靠性四个维度上优化
4. Execute    → 产出可直接签名的交易对象，内置 fallback
```

## 二、核心对象：Quote / Route / Step

### 对象层级

```
Quote（单步）
  ├── id, type, tool
  ├── Action: {fromChain, toChain, fromToken, toToken, fromAmount, slippage}
  ├── Estimate: {toAmount, gasCosts, feeCosts, executionDuration...}
  └── transactionRequest: {to, data, value, gasLimit}
                     ↑ 可直接签名执行！

Route（多步）
  ├── fromChainId, toChainId, fromToken, toToken, fromAmount
  ├── toAmount（预期最终输出）
  └── steps: [Step₀, Step₁, ...]
                 ↓
          Step（原子操作）
            ├── type: "swap" | "cross" | "lifi" | "protocol"
            ├── tool: 桥或 DEX 名称
            ├── Action: 这一步的 from → to
            ├── Estimate: 这一步的预期输出
            └── transactionRequest（调用 stepTransaction 后填充）
```

### Step 类型

| type | 含义 | 例子 |
|------|------|------|
| `swap` | 同链 DEX 换币 | USDC→ETH 在 Uniswap |
| `cross` | 跨链桥转移 | Arbitrum USDC → Optimism USDC 走 Stargate |
| `lifi` | swap + cross 一步完成 | 桥+路由组合交易 |
| `protocol` | DeFi 协议交互 | 存入 Vault、质押 |

### Quote vs Route

| | Quote | Route |
|---|---|---|
| 端点 | `GET /quote` | `POST /advanced/routes` |
| 返回 | 单条最优 | 多条可选 |
| 步数 | 单步 | 多步 |
| 适合 | 简单转账 | 需要比较不同路径 |
| 套利用？ | 偶尔 | **主战场** |

## 三、怎么读一条路由报告

### API 调用格式

```
GET https://li.quest/v1/quote
  ?fromChain=1          ← 以太坊主网
  &toChain=42161        ← Arbitrum
  &fromToken=USDC       ← 支持地址或 symbol
  &toToken=USDC
  &fromAmount=1000000   ← 1 USDC（6 decimals）
  &fromAddress=0x...    ← 你的地址
  &slippage=0.005       ← 0.5%
```

### 路由报告关键字段 ↔ 模块 1 成本层映射

| 报告字段 | 含义 | 对应模块 1 哪层成本 |
|----------|------|-------------------|
| `estimate.toAmount` | 预期收到 token 数 | **屏幕价差**的具体体现 |
| `estimate.toAmountMin` | 滑点容忍下限 | **价格冲击 + 滑点**（模块 1 第五节） |
| `estimate.feeCosts` | 协议费（桥费/DEX fee） | **swap fee × 交易次数** |
| `estimate.gasCosts` | 各步 gas 估算 | **所有链的 gas 费** |
| `estimate.executionDuration` | 预估总秒数 | **区块确认时间窗口**（模块 1 第四节） |
| `action.slippage` | 允许滑点比例 | 套利利润缓冲区 |
| `steps[].tool` | 用哪个 DEX/桥 | 决定**流动性深度**（模块 1 第三节） |

### 一个读路由的心智模型

```
route.toAmount（预期到手）
  ├── 减去 route.steps[0].estimate.gasCosts
  ├── 减去 route.steps[0].estimate.feeCosts
  ├── ...每步重复...
  └── = 净收益（还要留 MEV 风险折扣）
```

## 四、三个目标，三种路由

### "最优"的三个定义

| 目标 | 关键词 | LI.FI 对应参数 | 套利场景适用 |
|------|--------|---------------|-------------|
| **最省钱** | Best price | `order=fewest_transactions` | 稳定币搬运（利润薄，省一分是一分） |
| **最快** | Fastest | `order=fastest` / 过滤慢桥 | MEV 敏感操作（价差窗口短） |
| **最低滑点** | Lowest slippage | 选深池子的路由 | 大资金套利（滑点反噬比 gas 更致命） |

### 套利场景下的 paradox

```
默认推荐 ≠ 套利最优

例子：
  Route A: 通过 1inch → Across，便宜 $2，但 90 秒
  Route B: 直接 Stargate，贵 $5，但 30 秒
  
  普通用户选 A（省 $2）
  套利者选 B（60 秒窗口里价差可能消失了，多花 $5 保确定性）
```

**套利者心理模型**：
- 最便宜的路径 ≈ 最多人用的路径 ≈ bot 最熟悉 → 被夹概率高
- 有时候**稍微贵一点但冷门**的路径，gas 竞争低，成功率更高
- 跨链套利场景：桥确认时间 >> gas 成本差异

## 五、LI.FI Advanced Routes：套利者的核心武器

### `/advanced/routes` 端点

与 `/quote` 的关键区别：**返回多条路由，你可以自己选**。

```bash
POST https://li.quest/v1/advanced/routes
{
  "fromChainId": 1,
  "toChainId": 42161,
  "fromTokenAddress": "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48",
  "toTokenAddress": "0xaf88d065e77c8cC2239327C5EDb3A432268e5831",
  "fromAmount": "1000000000",    # 1000 USDC (6 decimals)
  "fromAddress": "0x...",
  "options": {
    "slippage": 0.005,
    "order": "cheapest",         # cheapest | fastest | safest
    "maxNumberOfRoutes": 5       # 返回 5 条路径
  }
}
```

### 多路由比较：套利决策流程

```
Step 1: 获取 5 条路由
Step 2: 逐条计算净收益
  net[i] = route[i].toAmount
           - sum(gasCosts per step)
           - sum(feeCosts per step)
           - MEV 风险折扣（基于 executionDuration）
Step 3: 按净收益排序
Step 4: 检查 min(executionDuration) vs 价差窗口大小
Step 5: 选出实际可盈利的那条（可能不是 #1）
```

## 七、与模块 1 的衔接

```
模块 1 建立的框架:
  屏幕价差 → 减去各层成本 → 可执行净收益

模块 2 加入的工具:
  LI.FI 自动帮你算每层成本 → 你只需要判断净收益是否 > 0
  并且可以比较不同路径的成本结构差异
```

### 一个完整套利分析流水线（预览）

```
1. 发现价差（需要价格源，模块 3 会用 Hermes 构建）
2. 调用 LI.FI /advanced/routes（今天学的）
3. 解析每条路由的 gas/fee/时间
4. 用模块 1 公式算净收益
5. 加 MEV 风险折扣
6. 如果净收益 > 阈值 → 考虑执行
```

## 关键收获

1. **LI.FI = 路由引擎，不是 LP**：它整合 27 座桥 + 31 个 DEX，但不持有流动性
2. **Quote ≠ Route**：Quote 是单步即签交易，Route 是多步比较池
3. **路由报告的每个字段都能对应模块 1 的成本层**：`feeCosts`=swap fee, `gasCosts`=gas, `executionDuration`=时间窗口, `toAmountMin`=滑点
4. **套利场景下"最便宜"不一定是"最优"**：速度（价差窗口）、滑点（大资金反噬）常比省 $2 gas 更重要
5. **`/advanced/routes` 返回多条路由供比较**——这是套利策略构建的核心工具
