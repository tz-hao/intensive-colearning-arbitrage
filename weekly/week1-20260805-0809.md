### 1️⃣ 套利地图：机会在哪（模块 1，08-05）

#### 1.1 AMM 自动做市商：DeFi 定价的底层逻辑

**恒定乘积公式：`x × y = k`**

- `x` = 池子里 Token A 的数量
- `y` = 池子里 Token B 的数量
- `k` = 恒定乘积（swap 过程中不变，直到有人提供/移除流动性）

**价格由代币比例决定，不是挂单撮合**：

```
Token A 的价格（以 B 计价）= y / x
```

**算例**：ETH/USDC 池有 10 ETH + 20,000 USDC
- k = 10 × 20,000 = 200,000
- ETH 价格 = 20,000 / 10 = **2,000 USDC**

**Swap 时的价格冲击**：你买入时池子比例改变 → 实际成交价偏离当前显示价。交易越大，冲击越大。

用 2,000 USDC 在上述池子买 ETH：

```
(10 - Δx) × (20,000 + 2,000) = 200,000
Δx ≈ 0.91 ETH（而非按"标价"的 1 ETH）
```

→ 差额 0.09 ETH 就是**价格冲击**（滑点）。不是市场"坑你"，是 AMM 公式的数学必然。

**AMM vs Order Book**

| 维度 | AMM | Order Book |
|---|---|---|
| 对手方 | 池子（无对手方） | 其他交易者挂单 |
| 流动性 | 曲线上任意一点都可交易 | 依赖挂单深度 |
| 价格冲击 | 大额交易天然高滑点 | 看订单簿厚度 |
| 定价 | 公式自动算 | 买卖挂单撮合 |

#### 1.2 七种套利结构：机会的完整分类

**① DEX 内三角套利**（同 DEX，三池绕圈）
- 路径：`USDC → ETH → UNI → USDC`
- 原理：三个池子各自独立定价 → 绕一圈隐含汇率可能 ≠ 1 → 存在套利空间
- 特点：**原子执行**（单笔合约调用），无跨 DEX 风险；扣 3 × 0.3% swap fee 后利润薄

**② DEX 间套利**（同一链，不同 DEX 同币对）
- 便宜的池子买，贵的池子卖
- 特点：需要 flash loan 或原子多步调用；**MEV bot 重灾区**

**③ 跨链套利**（链 A 买便宜 → 桥搬运 → 链 B 卖贵）
- **致命缺陷：非原子**。桥确认期间价格可能变化；成本多一层桥费 + 价格风险
- 适用场景：稳定币、高速桥（LayerZero/Stargate）、极端脱锚

**④ 稳定币套利**
- USDC/USDT/DAI 应 = $1，池子短暂偏离时套利
- 特点：波动极小（0.1-0.5%），扣费后微利，靠大资金 + bot
- **真正的大钱在脱锚事件**：如 SVB 事件 USDC → $0.87，一次吃满

**⑤ 清算套利**（借贷协议）
- 借款人抵押率不足 → 清算人替他还债 → 拿走抵押品 + 清算奖励（5-10%）
- **本质不同：对手是人，不是池子**。不需要等价差——盯抵押率触线即动手
- 竞争极激烈（bot 拼 gas）

**⑥ MEV（排序套利）**：不是找价差，是抢交易排序
- **三明治**：抢在别人大单前买 → 大单推高价格 → 立刻卖出
- **抢跑**：看到有利可图交易，复制一份给更高 gas 抢先执行
- **尾随**：大单后反向操作
- 启示：MEV searcher 和套利者抢同一块蛋糕——你的套利交易随时可能被抢

**⑦ 统一视角（分类树）**

```
                  ┌─ 同 DEX 内三角套利
  单链（原子）──┤
                  └─ 跨 DEX 价差套利

                  ┌─ 跨链套利
  跨链（非原子）─┤
                  └─ 稳定币脱锚搬运

                  ┌─ 清算套利（盯抵押率）
  非交易套利 ────┤
                  └─ MEV（抢排序）
```

#### 1.3 流动性深度：池子有多少"货"可以吃

AMM 的瞬时价格不回答一个关键问题：**这个价格能成交多少量**。

**薄池 vs 厚池**（同样 $2,000/ETH 的池子）

| | 薄池 | 厚池 |
|---|---|---|
| 规模 | 10 ETH + 20k USDC | 10,000 ETH + 20M USDC |
| 买 1 ETH 均价 | ~$2,100（滑点 ~5%） | ~$2,000.2（滑点 ~0.01%） |
| 屏幕价差 1% | 滑点吃掉全部利润 ❌ | 滑点可忽略，能赚 ✅ |

**结论：价差本身不说明任何问题——得看价差在多大交易量上还存在。**

**TVL ≠ 有效深度**
- **Uniswap V2**：流动性均匀分布整条曲线 `[0, ∞]`，只有当前价格附近有用
- **Uniswap V3**：集中流动性，LP 在指定价格区间放钱 → 同样 TVL，有效深度远高于 V2

套利时只关心**当前价格 ± 交易量范围**那段流动性。

**对净收益公式的影响**：滑点不是常数——它跟投入的**资金量**和池子的**深度曲线**绑定。优化套利 = 算出最优交易量，刚好榨干价差且不超过滑点反噬临界点。

#### 1.4 区块确认：价差是移动靶

**链不是实时的**。以太坊 ~12s 出一个块，你的交易进入 mempool 后才可能被打包：

```
T=0s   发现价差，提交交易 → mempool
T=6s   别人也提交了同样的交易
T=12s  出块！矿工打包了别人的，不是你的
       → 价差被吃掉，你还付了 gas 😵
```

**mempool 公开可见** → 你的交易意图暴露 → bot 抢跑。

**三层时间损耗**

```
看到价差 ─→ 签交易 ─→ 进 mempool ─→ 被打包
  ↑            ↑          ↑            ↑
 数据延迟   计算延迟   gas 竞争      12s 间隔
```

- **数据延迟**：RPC 节点可能慢 2-3 秒
- **mempool 可见**：bot 监听到后复制你的交易 + 更高 gas 插队
- **区块重组（reorg）**：以为上链了，实际被回滚

**对套利地图的影响**

```
屏幕价差（静态）
  → 时间窗口修正（抓取↔执行之间可能消失）
  → mempool 竞争修正（被看到就会被抢）
  → 区块位置不确定性（同块内顺序？）
```

**生存法则**：能活的套利要么**快到绕过公开 mempool**（Flashbots）、要么**利润薄到 bot 不屑抢**、要么**特殊到 bot 脚本没覆盖**。

这也解释了为什么"屏幕价差 90% 是幻觉"——不是价差不存在，而是在执行窗口中被抢/被吃/被吞了。

### 2️⃣ 净收益公式：能不能赚（模块 1，贯穿全程）

**公式（完整版）**

```
净收益 = 价差
  - swap fee × 交易次数
  - 每次交易的价格冲击（滑点）
  - 所有链的 gas 费
  - 桥费（若有跨链）
  - MEV 风险折扣（可能被抢跑）
  - 资金占用机会成本
```

**逐项解读**：

| 成本项 | 是什么 | 什么时候出现 |
|---|---|---|
| swap fee | 每笔 swap 付给 LP 的手续费（V2 0.3%） | 每笔交易都扣 |
| 价格冲击/滑点 | 你的交易自己推动价格 | 大额交易必现，深度越薄越狠 |
| gas 费 | 区块空间费用 | 每笔交易都扣；跨链 ≥ 2 笔 |
| 桥费 | 跨链桥协议费 + 流动性费 | 仅跨链时 |
| MEV 风险折扣 | 被抢跑/被夹的概率成本 | bot 密集区必须打折扣 |
| 资金占用 | 桥接期间资金锁死的机会成本 | 跨链、长确认时 |

**关键教训**：**90% 的屏幕价差扣除上述成本后为负或接近于零**。真正能执行的套利需要：
- 大资金（摊薄 gas 占比）
- 低延迟执行
- 避开 MEV 竞争
- 或等待极端事件（脱锚 / 巨鲸砸盘 / 新池启动）

### 3️⃣ LI.FI 路由引擎：怎么走最划算（模块 2，08-06）

#### 3.1 定位：不是 LP，是路由引擎

```
Uniswap:     你有钱，池子有钱，直接交易
LI.FI:       你不关心对手方是谁 —— 你只说"从哪到哪"
             它扫描所有 DEX + 所有桥，算最优路径
```

**LI.FI 聚合的对象（五层）**：

| 层级 | 聚合内容 | 例子 |
|---|---|---|
| DEX | 所有链上 DEX 流动性 | Uniswap V3, PancakeSwap, Curve, Balancer |
| DEX Aggregator | 聚合器本身 | 1inch, Paraswap, 0x, OpenOcean |
| 桥 | 跨链桥协议 | Stargate V2, Across, Relay, cBridge, Hop |
| Solvers | 意图执行网络 | 基于竞争的 solver 报价 |
| Yield | 收益协议 | 各种 Vault、Staking（通过 Composer） |

**四个核心动作**：

```
1. Aggregate  → 扫描所有桥、DEX、Solver、收益协议
2. Normalize  → 抹平 USDC vs USDC.e、不同链 token 地址差异
3. Calculate  → 在价格/速度/Gas/可靠性四个维度上优化
4. Execute    → 产出可直接签名的交易对象，内置 fallback
```

#### 3.2 核心对象：Quote / Route / Step

**对象层级**

```
Quote（单步）
  ├── id, type, tool
  ├── Action: {fromChain, toChain, fromToken, toToken, fromAmount, slippage}
  ├── Estimate: {toAmount, gasCosts, feeCosts, executionDuration...}
  └── transactionRequest: {to, data, value, gasLimit}
                     ↑ 可直接签名执行！

Route（多步）
  ├── fromChainId, toChainId, fromToken, toToken, fromAmount
  ├── toAmount（预期最终输出）
  └── steps: [Step₀, Step₁, ...]
                 ↓
          Step（原子操作）
            ├── type: "swap" | "cross" | "lifi" | "protocol"
            ├── tool: 桥或 DEX 名称
            ├── Action: 这一步的 from → to
            ├── Estimate: 这一步的预期输出
            └── transactionRequest（调用 stepTransaction 后填充）
```

**Step 四种类型**

| type | 含义 | 例子 |
|---|---|---|
| `swap` | 同链 DEX 换币 | USDC→ETH 在 Uniswap |
| `cross` | 跨链桥转移 | Arbitrum USDC → Optimism USDC 走 Stargate |
| `lifi` | swap + cross 一步完成 | 桥+路由组合交易 |
| `protocol` | DeFi 协议交互 | 存入 Vault、质押 |

**Quote vs Route**

| | Quote | Route |
|---|---|---|
| 端点 | `GET /quote` | `POST /advanced/routes` |
| 返回 | 单条最优 | 多条可选 |
| 步数 | 单步 | 多步 |
| 适合 | 简单转账 | 需要比较不同路径 |
| 套利用？ | 偶尔 | **主战场** |

#### 3.3 怎么读一条路由报告

**API 调用格式**

```
GET https://li.quest/v1/quote
  ?fromChain=1          ← 以太坊主网
  &toChain=42161        ← Arbitrum
  &fromToken=USDC       ← 支持地址或 symbol
  &toToken=USDC
  &fromAmount=1000000   ← 1 USDC（6 decimals）
  &fromAddress=0x...    ← 你的地址
  &slippage=0.005       ← 0.5%
```

**路由报告关键字段 ↔ 模块 1 成本层映射**

| 报告字段 | 含义 | 对应模块 1 哪层成本 |
|---|---|---|
| `estimate.toAmount` | 预期收到 token 数 | **屏幕价差**的具体体现 |
| `estimate.toAmountMin` | 滑点容忍下限 | **价格冲击 + 滑点** |
| `estimate.feeCosts` | 协议费（桥费/DEX fee） | **swap fee × 交易次数** |
| `estimate.gasCosts` | 各步 gas 估算 | **所有链的 gas 费** |
| `estimate.executionDuration` | 预估总秒数 | **区块确认时间窗口** |
| `action.slippage` | 允许滑点比例 | 套利利润缓冲区 |
| `steps[].tool` | 用哪个 DEX/桥 | 决定**流动性深度** |

**读路由的心智模型**

```
route.toAmount（预期到手）
  ├── 减去 route.steps[0].estimate.gasCosts
  ├── 减去 route.steps[0].estimate.feeCosts
  ├── ...每步重复...
  └── = 净收益（还要留 MEV 风险折扣）
```

#### 3.4 三个目标，三种路由

| 目标 | 关键词 | LI.FI 对应参数 | 套利场景适用 |
|---|---|---|---|
| **最省钱** | Best price | `order=fewest_transactions` | 稳定币搬运（利润薄，省一分是一分） |
| **最快** | Fastest | `order=fastest` / 过滤慢桥 | MEV 敏感操作（价差窗口短） |
| **最低滑点** | Lowest slippage | 选深池子的路由 | 大资金套利（滑点反噬比 gas 更致命） |

**套利场景下的 paradox（默认推荐 ≠ 套利最优）**

```
例子：
  Route A: 通过 1inch → Across，便宜 $2，但 90 秒
  Route B: 直接 Stargate，贵 $5，但 30 秒

  普通用户选 A（省 $2）
  套利者选 B（60 秒窗口里价差可能消失了，多花 $5 保确定性）
```

**套利者心理模型**：
- 最便宜的路径 ≈ 最多人用的路径 ≈ bot 最熟悉 → 被夹概率高
- 有时候**稍微贵一点但冷门**的路径，gas 竞争低，成功率更高
- 跨链套利场景：桥确认时间 >> gas 成本差异

#### 3.5 Advanced Routes：套利者的核心武器

与 `/quote` 的关键区别：**返回多条路由，你可以自己选**。

```bash
POST https://li.quest/v1/advanced/routes
{
  "fromChainId": 1,
  "toChainId": 42161,
  "fromTokenAddress": "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48",
  "toTokenAddress": "0xaf88d065e77c8cC2239327C5EDb3A432268e5831",
  "fromAmount": "1000000000",    # 1000 USDC (6 decimals)
  "fromAddress": "0x...",
  "options": {
    "slippage": 0.005,
    "order": "cheapest",         # cheapest | fastest | safest
    "maxNumberOfRoutes": 5       # 返回 5 条路径
  }
}
```

**多路由比较：套利决策流程**

```
Step 1: 获取 5 条路由
Step 2: 逐条计算净收益
  net[i] = route[i].toAmount
           - sum(gasCosts per step)
           - sum(feeCosts per step)
           - MEV 风险折扣（基于 executionDuration）
Step 3: 按净收益排序
Step 4: 检查 min(executionDuration) vs 价差窗口大小
Step 5: 选出实际可盈利的那条（可能不是 #1）
```

### 4️⃣ 执行成本五问：为什么不能只看两个价格（模块 3 Day1，08-07）

#### 4.1 核心问题

```
① 资金在哪里？  ② 走哪条路？  ③ 多久到达？  ④ 实际收到多少？  ⑤ 中间损耗多少？
```

**「价差 → 净收益」的完整链路**：

```
① 发现价差          → 两个市场（或同市场不同池）的价格差
② 确认资金位置      → token 在哪个链？需要先 swap 还是桥？
③ 计算路径成本      → LI.FI 算：gas + 桥费 + DEX fee + 滑点
④ 估算时间窗口      → executionDuration vs 价差持续时间
⑤ 评估 MEV 风险     → 这条路径是不是 bot 密集区？
⑥ 得到净收益        → toAmount - 总成本 - MEV 折扣
⑦ 判断是否执行      → 净收益 > 阈值（否则不做）
```

**核心洞察：套利不是「发现机会」，是「验证机会是否可执行」。发现价差只占流程 20%，剩下 80% 是执行验证。**

#### 4.2 五项摩擦成本详解

**① Gas 费（所有链的燃料）**
- 每笔交易都要付 gas，跨链套利 = 至少 2 笔（买 + 卖），跨链还可能有桥接费
- 例：价差 $10，但主网 gas 两笔加起来 $8 → 净收益只剩 $2

**② 桥费（跨链的过路费）**
- 跨链必须走桥，桥收协议费 + 依赖流动性深度
- 例：Stargate 收 $5 固定费 + 0.06% 滑点费，**小金额搬运直接亏**

**③ 滑点（你的交易自己推动价格）**
- 大额交易会吃掉池子深度，实际成交价 ≠ 报价价
- AMM 里买 100 ETH 的均价远高于买 1 ETH
- **价差可能只有 0.3%，但你的交易滑点就 0.5% → 直接倒亏**

**④ MEV（机器人抢跑）**
- 你看到的价差，bot 也看得到，而且比你快
- 最便宜路径 ≈ 最多人用 ≈ 被夹概率最高（三明治攻击）
- 时间窗口：`executionDuration` 如果 > 价差存在时间，你到的时候价差已经没了

**⑤ 隐性成本**
- **资金占用**：桥接要等确认（几分钟到几十分钟），期间资金锁死
- **失败交易**：滑点设置太紧 → 交易失败 → gas 白付
- **跨链最终性**：有些桥需要挑战期/预言机确认

#### 4.3 结论

```
只看两个市场的价格 = 只看收入，不看成本
真实的净收益 = 价差 - gas - 桥费 - 滑点 - MEV折扣 - 失败概率×gas

所以：执行前必须拿到「真实报价」→ 这就是为什么 LI.FI 的价值
不在于告诉你哪里有价差，而在于把执行成本精确算给你看
```

#### 4.4 LI.FI 四种 Agent 接入方式盘点

| 方式 | 接入途径 | 适用场景 |
|---|---|---|
| **REST API** | `https://li.quest/v1/*`（quote/routes/status/chains/tokens/tools） | **最快起步**：脚本/Agent 直接 HTTP 调用，无需 API Key，适合信号验证和原型 |
| **MCP Server** | LI.FI 托管的 MCP 端点 | **LLM 原生**：Claude/Cursor/Hermes 等支持 MCP 的 Agent 直接"对话式"查报价、追状态，适合研究探索 |
| **SDK** | `@lifi/sdk`（npm, TypeScript） | **产品集成**：把 LI.FI 路由能力嵌进自己的应用/交易系统，完全控制执行流程，适合策略落地 |
| **CLI** | `npx @lifi/cli` | **终端快速查询**：人肉/脚本在命令行查一条报价，token 开销最小，适合调试和快速验证 |

**对 Hermes 的意义**：Hermes 是 MCP 客户端——**可以直接挂 LI.FI 的 MCP Server**，让 Agent 拥有「查报价 → 比较路由 → 判断净收益」的链上套利能力。这正是模块 3 要搭的工作流核心。

### 5️⃣ 信号工作流：怎么自动化（模块 3 Day2，08-08）

#### 5.1 五环节流水线

```
① 价格源采集 → ② 价差计算 → ③ LI.FI 报价 → ④ 净收益判断 → ⑤ 告警/信号
   CoinGecko      (askA-bidB)    /quote       toAmount-成本    净收益>阈值
   链上 RPC       -桥费-gas      /routes      -MEV折扣         →推送
```

**每环节的输入/输出**：

| 环节 | 输入 | 输出 |
|---|---|---|
| ① 采集 | 链/合约地址列表 | 各市场实时价格 |
| ② 价差 | 两个市场价格 | spread（毛价差） |
| ③ LI.FI 报价 | 起链/目的链/token/金额 | toAmount + 费用明细 + 时长 |
| ④ 净收益 | 报价结果 | 通过/拒绝 二元信号 |
| ⑤ 告警 | 通过的信号 | 群聊推送 |

**核心认知**：② 的毛价差不能直接决策，必须经过 ③ 把成本算进去，才能得到 ④ 的真净收益。

#### 5.2 数据源选择（关键决策）

| 数据源 | 拿到的数据 | 延迟 | 用途 |
|---|---|---|---|
| CoinGecko 聚合价 | 全局均价（不分链） | 1-5 min | 粗筛 |
| CoinGecko token_price | 某链某合约价格 | 1-5 min | 粗筛 |
| 链上 RPC (eth_call getReserves) | 池子实时储备 → 可成交价 | 实时 | 精确验证 |
| Subgraph | 历史池子数据 | 索引延迟 | 回测 |

**决策**：先跑通最小闭环 **CoinGecko 粗筛 → LI.FI 验证**。理由：
- 聚合价延迟 1-5 min 对「分钟级窗口」的套利不够精确，但足够做第一层漏斗
- LI.FI 报价自带全部成本（桥费+gas+滑点），是净收益的权威来源
- 链上 RPC 读池子代码量最大，留到 08-10 信号校准阶段再上

**RPC 读池子原理**（预研）：

```
reserve0, reserve1 = pair.getReserves()   # eth_call 只读调用
price_token0_in_token1 = reserve1 / reserve0
```

#### 5.3 LI.FI 报价（工作流的心脏）

**请求参数**（设计期定死的字段）：

```
GET https://li.quest/v1/quote
  fromChain   = arbitrum
  toChain     = ethereum
  fromToken   = <USDC-Arbitrum 合约地址>
  toToken     = <USDC-Ethereum 合约地址>
  fromAmount  = 10000000000   # 10,000 USDC × 10^6 decimals
  fromAddress = <钱包地址>
  slippage    = 0.005
```

**只关心 4 个返回字段**：

| 字段 | 含义 |
|---|---|
| `route.toAmount` | 最终到账（已扣所有费用）→ 净收益核心 |
| `estimate.gasCosts[]` | gas 明细 |
| `estimate.feeCosts[]` | 桥费/DEX fee 明细 |
| `estimate.executionDuration` | 发起到到账秒数 → 和价差窗口比 |

**设计哲学**：跨链同币时净收益 = toAmount - fromAmount，LI.FI 把成本全算进 toAmount，不用手工减。

#### 5.4 净收益判断（决策闸门）

```
净收益(USD) = toAmount(折算USD) - fromAmount(USD)
收益率      = 净收益 / fromAmount

触发条件（粗版，08-13 精修）：
  ① 净收益 > $10
  ② 收益率 > 0.3%
  ③ executionDuration < 预估价差存续时间
  ④ MEV 折扣：bot 密集区 → 预期收益 × 0.5 后再比阈值
```

**算例（示意值）**：

```
10,000 USDC：Arbitrum → Ethereum
  spread（毛）      = +0.15%  → 毛利 $15
  LI.FI 桥费+gas   ≈ -$18    → 净亏 $3 ❌
结论：桥费是固定成本，小额搬运永远亏 — 价差 ≠ 利润的实锤
```

- 通过闸门 → 群聊推送，格式：

## 四、本周五大认知升级

1. **90% 的屏幕价差是幻觉**——不是不存在，而是在执行窗口中被抢/被吃/被吞
2. **毛价差不能决策**——必须经 LI.FI 报价把成本算进 `toAmount`，才是真净收益
3. **桥费是固定成本**——小额搬运天然不经济，信号阈值必须覆盖固定成本
4. **最便宜路径 ≈ bot 最熟路径**——冷门但稍贵的路径 gas 竞争低，成功率更高
5. **跨链同币净收益 = toAmount - fromAmount**——LI.FI 把费用全扣净，不用手工减
